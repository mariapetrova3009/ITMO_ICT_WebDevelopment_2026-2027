4. Реализация REST API

REST API я реализовала с помощью Django REST Framework. Запросы к гостинице имеют общий префикс /api/, данные передаются в формате JSON.

Адреса API ниже приведены как текстовые примеры HTTP-запросов. Они относятся к запущенному Django-приложению. GitHub Pages публикует только отчёт MkDocs и не обрабатывает запросы к /api/. Для переходов между разделами отчёта используется верхнее меню.

Основную реализацию распределила по четырём файлам:

  • models.py — модели базы данных, связи и ограничения.
  • serializers.py — проверка входных данных и преобразование данных для API.
  • views.py — обработка запросов и формирование ответов.
  • services.py — основная логика заселения, выселения, увольнения сотрудника и расчёта квартального отчёта.

Например, GET /api/rooms/ возвращает номера, а POST /api/rooms/ создаёт новый номер. Запрос GET /api/guests/ возвращает список гостей, а POST /api/guests/ регистрирует гостя. Для сотрудников предусмотрены GET /api/employees/ и POST /api/employees/. Для отдельных номеров, гостей и сотрудников доступны просмотр, изменение и удаление по ID с учётом ограничений приложения.

Заселение выполняется запросом POST /api/check-in/. В нём передаются ID номера, массив ID гостей и даты проживания. Список заселений можно получить через GET /api/accommodations/, а выселение оформить через POST /api/accommodations/<id>/check-out/, указав фактическую дату выезда. Заселения и связи с гостями доступны для чтения; их создание выполняется через операцию заселения.

Для просмотра расписания уборки используется GET /api/cleaning-schedules/, для добавления назначения — POST /api/cleaning-schedules/, для просмотра расписания сотрудника — GET /api/employees/<id>/schedule/. Увольнение оформляется через POST /api/employees/<id>/dismiss/: система также завершает действующие и отменяет будущие назначения на уборку.

Пример результата CRUD-запроса

Пример запроса списка номеров:

GET /api/rooms/

В ответе возвращается массив номеров с их ID, этажами, типами и телефонами.
