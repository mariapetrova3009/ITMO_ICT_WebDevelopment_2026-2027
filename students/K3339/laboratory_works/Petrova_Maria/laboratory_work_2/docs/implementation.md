# Реализация

Основной код находится в приложении `project_first_app`. В `models.py` описаны данные, в `forms.py` — формы, в `views.py` — обработка запросов, а в `urls.py` — адреса страниц. Работа с базой выполняется через Django ORM.

## Регистрация пользователей

Представление `register` использует `UserCreationForm`. Пользователь вводит имя и дважды пароль. Если форма заполнена правильно, аккаунт сохраняется, после чего открывается страница входа. Для входа и выхода используются стандартные представления Django.

## Просмотр номеров

Представление `room_list` выводит список номеров. В карточке видны отель, тип, стоимость и вместимость. В `room_detail` показаны подробности номера, удобства и отзывы.

Страницы оформлены шаблонами Jinja2. В `django_project_petrova/jinja2.py` подключены функции для ссылок и статических файлов, а также фильтр форматирования дат и чисел.

## Бронирование

Пользователь открывает номер и выбирает даты заезда и выезда. Представление `create_reservation` передаёт номер в `ReservationForm` до проверки формы. Пользователь берётся из текущего аккаунта.

Метод `clean()` проверяет условие `check_out > check_in`. Если выезд раньше заезда или в тот же день, форма показывает: «Дата выезда должна быть позже даты заезда».

Затем проверяются другие бронирования этого номера. Периоды пересекаются, когда новый заезд раньше существующего выезда, а новый выезд позже существующего заезда. В форме используется такой запрос:

```python
reservations = Reservation.objects.filter(
    room_id=self.instance.room_id,
    check_in__lt=check_out,
    check_out__gt=check_in,
).exclude(pk=self.instance.pk)
```

Если запись найдена, появляется ошибка «Номер уже забронирован на выбранные даты». Новая бронь не сохраняется. Заезд в день выезда предыдущего гостя разрешён.

## Редактирование и удаление бронирования

В `my_reservations` выводятся бронирования текущего пользователя. Через `edit_reservation` можно изменить даты, а через `delete_reservation` — удалить запись после подтверждения.

Оба представления ищут запись по её идентификатору и текущему пользователю. Поэтому изменить или удалить чужую бронь нельзя. При редактировании используется та же форма. Текущая запись исключается из проверки пересечений и не конфликтует сама с собой.

## Отзывы

Представление `create_review` использует `ReviewForm`. Пользователь вводит период проживания, текст и оценку от 1 до 10. Автор и номер записываются в представлении.

Форма проверяет `stay_to > stay_from`. При ошибке выводится: «Дата окончания проживания должна быть позже даты начала». Проверка фактического проживания пользователя не выполняется. Сохранённые отзывы видны на странице номера.

## Фильтрация и поиск

Поиск выполняется по части названия отеля без учёта регистра: `hotel__name__icontains`.

В списке номеров есть фильтры:

- по типу номера — `room_type_id`;
- по минимальной вместимости — `capacity__gte`;
- по максимальной стоимости — `price__lte`.

Поиск и фильтры можно использовать вместе.

## Пагинация

В `room_list` используется `Paginator(rooms, 6)`. На одной странице выводится до 6 номеров. При переходе между страницами в ссылках сохраняются значения поиска и фильтров.

## Таблица постояльцев

Представление `recent_guests` выводит проживания, которые пересекаются с последними 30 днями. Для отбора используется `Q`.

Заселение должно быть не позже текущего времени. Дата выезда должна быть пустой или попадать в последние 30 дней. Поэтому в таблицу входит и гость, который заселился раньше, но выехал недавно. Полностью завершённые до этого периода проживания не выводятся.

Записи отсортированы по `check_in` от новых к старым. Таблица доступна только сотрудникам с `is_staff`.
