# Практическая работа 2.1

Проект Django с четырьмя моделями: CarOwner, Car, Ownership и DriverLicense.
Ownership хранит даты владения и связывает владельцев с автомобилями через through.
Тип удостоверения выбирается из списка choices. Поля DateTimeField и null соответствуют схеме задания.

## Запуск на macOS

Команды выполняются из папки practical_works:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py loaddata sample_data
python manage.py createsuperuser
python manage.py runserver
```

На Windows окружение создаётся командой `py -m venv .venv`,
а активируется командой `.venv\Scripts\activate.bat` в cmd.

Миграция уже сохранена в проекте. После изменения моделей:
```bash
python manage.py makemigrations
python manage.py migrate
```

## Страницы

- http://127.0.0.1:8000/owner/1/ - первый владелец.

## Практическая работа 2.2

Связь CarOwner.cars использует промежуточную модель Ownership с датами
start_date и end_date. Изменение схемы базы для этой работы не потребовалось.

Владельцы:
- /owners/ - список, функция owner_list.
- /owners/create/ - добавление через CarOwnerForm, функция owner_create.
- /owner/1/ - просмотр владельца.

Автомобили:
- /cars/ - список, CarListView.
- /cars/1/ - просмотр, CarDetailView.
- /cars/create/ - создание, CarCreateView.
- /cars/1/update/ - изменение, CarUpdateView.
- /cars/1/delete/ - подтверждение удаления, CarDeleteView.

Создание и изменение автомобиля используют CarForm.
Удаление выполняется POST-запросом после подтверждения.
Все формы содержат CSRF-токен и выводят ошибки ввода.
Главная страница также показывает список владельцев.

В локальной базе теперь 6 владельцев и 7 автомобилей.
Третий владелец, ещё три владельца и три автомобиля добавлены через формы
POST-запросами Django Client с включённой проверкой CSRF.
Дополнительные записи сохранены в practice_2_data.json.
Чтобы восстановить данные обеих практик в новой базе:

```bash
python manage.py migrate
python manage.py loaddata sample_data practice_2_data
```

## Практическая работа 2.3

CarOwner теперь наследуется от AbstractUser и является моделью пользователя.
В settings.py установлено AUTH_USER_MODEL = "project_first_app.CarOwner".
Ownership и DriverLicense ссылаются на settings.AUTH_USER_MODEL.

Добавлены passport_number (номер паспорта), home_address (домашний адрес)
и nationality (национальность). Поля отображаются на странице пользователя
и в Django Admin при создании и редактировании.

Форма /owners/create/ основана на UserCreationForm: запрашивает логин,
пароль с подтверждением и данные владельца. Пароль сохраняется в виде хеша.
Форма проверяет совпадение паролей, уникальность логина и обязательные поля.

Текущая база: db_users.sqlite3. Прежняя db.sqlite3 оставлена как резервная
копия данных до перехода. Начальная миграция пересоздана для новой базы:
применять её поверх старой базы нельзя. Команды запуска выше используют
новую базу автоматически.

В новую базу перенесены владельцы, автомобили, удостоверения, периоды
владения и администратор с прежним паролем. Старые сеансы и журнал админки
остаются в прежней базе. Логины прежних владельцев: owner1–owner6.
Для них пароль не задан; его можно установить через админку.
Новые персональные поля у прежних записей пустые, поскольку этих данных
раньше не было. Их можно заполнить через админку.
Теперь администратор также отображается в общем списке пользователей.

При восстановлении fixtures создаются учебные владельцы без паролей;
администратор создаётся отдельно командой createsuperuser.
Описание перехода: https://docs.djangoproject.com/en/5.2/topics/auth/customizing/
