Модель данных

Данные хранятся в PostgreSQL. Модели приложения описаны в project_first_app/models.py. Пользователь берётся из стандартной системы авторизации Django.

User

Используется стандартная модель django.contrib.auth.models.User. В проекте нужны имя пользователя username, пароль password и признак сотрудника is_staff. Пароль хранится в виде хеша. Связи с пользователем заданы через settings.AUTH_USER_MODEL.

Hotel

Хранит информацию об отеле:

  • name — название;
  • owner_name — имя владельца;
  • address — адрес;
  • description — описание, которое можно оставить пустым.

RoomType

Хранит тип номера: name — название и description — необязательное описание.

Amenity

Хранит удобство номера. Поле name содержит его название, например Wi-Fi.

Room

Хранит сведения о номере:

  • hotel — отель;
  • room_type — тип номера;
  • number — обозначение номера;
  • price — стоимость;
  • capacity — вместимость;
  • amenities — удобства;
  • description — необязательное описание.

Reservation

Хранит бронирование:

  • user — пользователь;
  • room — номер;
  • check_in и check_out — даты заезда и выезда;
  • created_at — время создания записи, заполняется автоматически.

Stay

Хранит запись о проживании. Поля user и room указывают пользователя и номер. Поля check_in и check_out содержат дату и время заселения и выселения. Пока человек проживает, check_out остаётся пустым.

Review

Хранит отзыв о номере:

  • user — автор;
  • room — номер;
  • stay_from и stay_to — даты периода проживания;
  • text — текст отзыва;
  • rating — оценка от 1 до 10;
  • created_at — время создания, заполняется автоматически.

Ограничение оценки задано валидаторами MinValueValidator(1) и MaxValueValidator(10).

Связи моделей

ForeignKey связывает номер с отелем и типом номера. Через него бронирования, проживания и отзывы связаны с пользователем и номером. Одному отелю соответствует несколько номеров. У пользователя и номера может быть несколько бронирований, проживаний и отзывов.

ManyToManyField используется для Room.amenities: у номера может быть несколько удобств, а одно удобство может встречаться в разных номерах.

В схеме ниже стрелка идёт от записи к модели, на которую она ссылается:

Room        → Hotel
Room        → RoomType
Room        ↔ Amenity
Reservation → User, Room
Stay        → User, Room
Review      → User, Room

Reservation и Stay — отдельные записи. Прямой связи между ними в модели нет.
